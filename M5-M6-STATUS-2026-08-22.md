### C-4 — the deployed `SKILL.md` silently reverted 55 lines of committed documentation

`git HEAD` (`c756c85dbc`, committed **17:51:30**) contains a 55-line section:

> `### Re-signing reviewed-startup-pack-manifest.json (added 2026-08-22, reverse-engineered — no dedicated tool exists)`

The `SKILL.md` deployed to `~/.agents/skills/orca-context-bridge/` at **20:09:24** — two and a half hours later — **does not contain it**. Verified by diffing `git show HEAD:orca-context-bridge/SKILL.md` against the deployed copy: hunk `623,677d622`, 55 lines deleted, and no compensating content.

Line accounting, which resolves cleanly:

- `git HEAD` = 849 lines (includes the re-signing section)
- deployed = 862 lines (= HEAD − 55-line re-signing section + M4's round-3 doc rewrite)
- workspace = 997 lines (= deployed + 55-line re-signing section restored + M6's 80-line `### Searching the catalog`)
- `git diff --stat` vs HEAD = **161 insertions / 13 deletions** = M4 round-3 rewrite (+81/−13) + M6 section (+80). Exact match, which independently confirms the M6 reviewer's attribution that M6's own contribution is the appended hunk only.

So the M4 deploy was built from a `SKILL.md` baseline that predates a committed section from a **different** workstream (the manifest re-signing procedure), and pushed that regression onto the shared skill directory that serves every project. Impact is documentation-only — no code path changes — but the lost content is live operational knowledge, and per the session's own history `authority_git.head` re-signing has been needed repeatedly. An agent reading the deployed skill today cannot find the procedure.

**Silver lining for M6:** deploying the current workspace `SKILL.md` would *restore* the lost section. That must be done by copying the workspace file wholesale, not by patching the deployed one — see the checklist in §7.
