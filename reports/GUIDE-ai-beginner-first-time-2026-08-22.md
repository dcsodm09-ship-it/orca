## 先认路(30 秒)

打字给我、看我回复——这件事本身,就是以后开发时你要做的核心动作。

但接下来屏幕上除了我们的对话,还可能冒出别的东西:一堆你看不懂的英文、闪烁的黑底窗口、突然弹出来的按钮、旁边一列文件名。**这些先当看不见就行,不是要你学的功课**,具体怎么应对后面会讲。你只需要认清两个地方:

1. **能打字的那一格**——你跟我说话的地方
2. **我做完之后打开的预览窗口,或者发在对话里的图**——那是"效果",也是你唯一需要看的东西

---

## 一句话打消你的顾虑

**你不需要会写代码。你只需要能把"我想要什么"讲清楚,剩下的交给我。**

代码、文件夹、命令行这些,平时都由我来动,你不用学。但有几件小事你偶尔会遇到,不是出错了,是正常的:

- 我要做一件会真的改动东西的事之前,屏幕可能会弹出一个框问你"允许吗"——这不需要你懂技术,看不懂就直接问我"这一步在干嘛",我解释完你再决定。
- 我说"打开看看效果"时,效果可能出现在另一个窗口。
- 离开电脑前,记得开口让我帮你存一下进度。

除此之外,你要做的核心事情只有两件:

1. **说清楚你想要什么**
2. **看完结果之后,说清楚哪里不对**

---

## 你现在心里可能在想的几件事

零基础的人,卡住往往不是因为"不会说需求",是因为心里有些没说出口的顾虑。下面直接对应成一句能说出口的话:

| 心里想的 | 你就说这句 / 事实是 |
|---|---|
| 我这个问题是不是太蠢了 | 没有蠢问题。"这是什么意思,用一句人话说"和一个很深的技术问题,对我完全一样。 |
| 我怕说错话,把东西弄坏 | 真正会改动文件、动电脑的动作都是我在做,而且危险操作我会先停下来问你。你打字,弄不坏任何东西。 |
| 我是不是在浪费它的时间 | 我没有情绪、不会累、不会不耐烦。你改第 1 次和改第 20 次,对我一样。 |
| 别人都会,就我不会 | 会写代码的人现在也是用和你完全一样的方式在跟我说话——说需求、看结果、提意见。你没落后,只是还没开始。 |
| 我不懂技术,会不会被糊弄 | 记住这句反制话术:"你刚才说的我没听懂,用买菜大妈能听懂的话再说一遍。"——听不懂是我表达的问题,不是你理解的问题。 |
| 屏幕全是英文,我是不是不该用这个 | 英文是我干活的后台,不是给你的考卷。复制那行字问我"这是在问我什么"就行。 |
| 是不是在偷偷花我的钱 | 正常使用不用你操心这个。唯一可能遇到的是用得特别密集时系统提示"歇一会儿再用"——那是用量节奏限制,不是收你钱,也不是你弄坏了什么。 |
| 做到一半不想做了怎么办 | 随时可以停。说一句"先存一下,今天不做了",东西都在,明天、下周回来接着做都行。 |

## 核心心法

```
你说目标  →  我做出来(有时会先问你一两句)  →  你看效果、亲手点一下  →  不对就说哪里不对  →  我改  →  再看……
```

一直重复这个循环,直到你满意为止。**不需要一次性想清楚全部细节**,做出第一版之后你反而更容易发现"哦原来我想要的是这样"——这很正常。

我有时会先问你一两句再动手,有时会直接开始做,两种都正常。不想被问太多,就在需求末尾加一句:**"先做一个能看的最简版,细节你先定,我看了再改。"**

## 第一句话,直接抄这三句里的一句

别想了,先动起来。选一句,把括号里的字改成你想要的,发出去就算开始了:

**① 完全没想法,只想先感受一下:**
> "我完全没用过这种东西。你先带我做一个最简单的小玩意儿,让我感受一下整个流程,做什么你来定。"

**② 心里有个想法,但说不清楚:**
> "我想先做一个最小能看的小东西:(在这里写你的想法,比如"记录每天喝了几杯水")。细节你先定一个最简单的,做完直接打开给我看,不要先给我看代码。"

**③ 想让我先问你(推荐第一次用的人试这句):**
> "我想做一个 ______。你先别动手,先问我最多 3 个问题,把你需要知道的信息问清楚,再开始做。"

第 ③ 句是个小技巧:它把"我说不清楚"的压力从你身上反转到我身上——变成我来问、你只要回答。任何时候觉得"我讲不明白",都可以说**"你先问我几个问题"**。

发出去之后:可能会安静一两分钟,也可能屏幕开始滚动很多英文——**这是在干活,不是卡住了**。这段时间不用再补发新需求,等我说"做好了"或者打开一个窗口,再看效果、给反馈。

还没想好第一次做什么?挑一个最小的:喝水计数、今天花了多少钱、三件待办事项、一张自我介绍单页。选最小的那个当第一局。

## 怎么把需求讲清楚

判断标准很简单:**你说的话,能不能让另一个人在脑子里想象出画面**。

**❌ 太模糊:**
> "帮我做个网站" / "做个记账的软件"

**✅ 具体到能想象出画面:**
> "我想做一个记录每天喝水量的小网页。打开能看到一个大大的数字,是今天喝了几杯水;下面一个按钮写着'+1杯',点一下数字加一;刷新页面后今天的数字还在;样式简单可爱,蓝色系。"

区别不在"要不要懂技术",在**要不要具体**,而且最好能顺带回答:**给谁用、按下按钮会发生什么、算成功的标准是什么**——不需要技术词,大白话就行。

**还没想清楚也没关系,直接说:**
> "我想做一个记账的小工具,具体长什么样还没想好,你先做一个最简单能用的版本,我看了再说要改什么。"

**"一次一个小目标"里,多小算小?** 检查方法:这件事能不能在你下次喝口水之前,看到一个能点的东西?不能,就再拆小一点。

## 做出来之后,照这几条检查

别只是"看一眼觉得还行"。看到东西之后,做这几件事(30 秒):

**① 亲手点一遍你最想要的那个功能。** 不是看一眼,是真的用鼠标点下去,看它是不是真的做了你想要的事。

**② 问一句:"这里面的数据是真的,还是你先随便填的?"** 为了先让你看到样子,我经常会先填一些假的示例数据。这是正常做法,但你不问,很容易把"看起来做好了"当成"真的做好了"。

**③ 刷新一下、关掉再打开,东西还在吗?** 很多第一版是"刷新就丢"的。如果你要的是"下次打开还能看到今天记的数据",就得自己试一次,并明确跟我说"我要刷新/关掉再打开数据还在"。

这三条里任何一条不对,直接说出来就行,不用想怎么措辞。

## 屏幕上开始滚一堆看不懂的东西了,怎么办

**那些滚动的字,你不用看懂。** 那是我在读文件、跑命令的过程,你只需要等最后那段给你看的话。

**突然停下来问你"允许吗",要选是或否。** 这不是出错了,是安全设计——我要做一件会真的改动东西的事,得先经过你。看不懂就直接问我"这一步在干嘛、会改什么",我解释完你再决定。选"不允许"不会有任何损失,我会换个做法或者问你怎么办。

**很久没动静。** 小东西一般几分钟内就有结果。久到你不安,直接打字问"现在在干嘛?",我会告诉你进度——**不要在这时候又发一条新需求**,会把当前这轮打乱。

**看到我贴出一大段代码。** 回一句"不要给我看代码,打开效果给我看"就行,不需要看懂。

**想中途喊停,随时可以。** 直接说"停一下"。停下来什么都不会坏。

## "做出来了"到底是什么意思

先把期望放对。第一周的成功标准只有这个:

> 你自己能在这台电脑上看见、能点、能让我按你的话改,并且存过一次档。

先不要拿这些当第一关:朋友在微信里就能打开、能在应用商店搜到、做成微信小程序、全网任何人都能访问。那些以后可以做,但要额外的账号、审核和费用,得你明确说"要发布"才会去做。

三个容易混的词:
- **网页**:在浏览器里打开的一页。第一版我们几乎都先做这个,因为最快能看见。
- **本地预览**:只在你这台电脑上能打开,关掉运行环境可能就停止,别人的设备打不开。
- **发布 / 上架**:让互联网上的人或应用商店能访问到,是单独的一步,涉及账号、审核和费用,要你明确说了才会做。

你如果说"做个 App",我多半会先给你做一个网页——不是敷衍,是让你今天就能看见、能改。真要装到手机上,你再明确说,我们另走一步,那一步会慢很多,不是今天必须做的。

## 新手要养成的几个习惯

1. **一次只提一个够小的目标。** 先说"先做出能看的第一版",看到东西之后再一点点加。目标很大的话,直接让我把它拆成几个阶段,只开始第一阶段。
2. **做完一点就要求"给我看看效果",并且亲手点一下。** 你永远只需要看效果,不需要看代码。
3. **觉得不对就直接说不对,不用道歉。** "这不是我想要的""颜色不对,我要红色的"——越直接的反馈,我改得越准,我不会不耐烦。
4. **随时可以喊停。** "停,不是这个""只改这一处,别的别动"——这和把需求说清楚一样重要,尤其是发现我开始往奇怪的方向走的时候。
5. **定期让我帮你存档。** 直接说"帮我把现在的进度存一下"。存的是这台电脑上的项目文件,不是我的记忆——这两者是两回事,下一节会讲。万一后面越改越糟,直接说"退回到上次存档的样子",我能把它还原。
6. **要有外部影响的事,先问能不能反悔。** 见下面"安全"这一节。

## 安全:记住这两条就够

**第一条:密码、验证码、密钥、身份证号、银行卡号、付款码/收款码这类东西,不要直接打在对话里。** 需要登录的时候,优先你自己在官方页面上点,不要图省事让我"替你登"。

万一已经贴进去了怎么办?(这很常见,不用慌,但要马上做两件事)
1. **立刻说出来**:"我刚才把密码贴进来了。"别憋着,我需要知道才能提醒你哪些地方留了痕迹。
2. **去把那个密码改掉。** 已经出现在对话记录里的,就当它不安全了,换一个新的。

**第二条:遇到可能反悔不了的操作,先问一句,哪怕我没主动问你。** 看到这些词提高警觉:删除、清空、发布/上线、安装、花钱、绑定你的账号、替你登录、把东西发给别人。直接说:

> **"这个操作能不能反悔?"**

"重要操作我会主动先问你"这句话我会尽量做到,但**这是我这边的自我要求,不是唯一的防线**——真正靠得住的,是你自己养成随口问这一句的习惯。不问也不会吃亏,问了永远不亏。

## 一个更接近真事的完整例子

假设你想要"喝水记录"这个小工具,对话大概会这样进行:

**你:** "我想先做一个最小能看的小网页:记录每天喝了几杯水。一个大数字,一个'+1杯'按钮,刷新后今天的数字还在,蓝色、简单就行。做完直接打开给我看,不要先给我看代码。"

**(屏幕安静了一会儿,然后滚了一段英文。你没有再发新消息,等着。)**

**我:** "做好了,已经打开。已经测试过:点击加一、刷新后数字保留。这是本地预览,还没有发布到网上。"

**你打开一看,数字太小,而且点了几次之后不太确定是不是真的记住了。你:** "数字太小,再放大一倍。另外我关掉浏览器再打开,数字还在吗?"

**我:** "数字放大了。测试了关闭再打开——目前只保存在这个浏览器里,换一台设备或者清了浏览器数据会丢。要不要我做成保存得更稳妥一点?"

**你:** "先不用,够用了。先存一下。"

**我:** 存档,并用大白话告诉你现在做到哪一步、还有什么没做。

**(几天后,你想接着做一个进度条功能,但打开的是一个新的对话窗口。)**

**你:** "我们之前做过一个喝水记录的网页,先看一下现在的样子,别新建一份。"

**我:** 会先去看项目里已经有的文件,确认清楚之后再接着改,不会从头重做一份。

不是所有事都会一次顺利——中途要求"你截图给我看"没截出来、我一时理解错了你的意思、屏幕上突然弹一个问你"允许吗"的框,都是正常会发生的事。遇到了,照前面几节说的话原样说一遍就行,不代表你做错了什么。

## 今天做到这、明天接着做

**收工前说这一句:**
> "帮我把今天做到哪、下一步打算做什么记下来。"

**第二天开工说这一句(不管开的是不是同一个窗口):**
> "我们之前在做 ______,先看一下项目里已经有的东西,告诉我现在做到哪、下一步是什么。"

**同一个对话窗口里,刚才说的我通常还记得。** 但换一个新对话、对话聊得太长、或者隔了一夜,我可能记不全——这不是你做错了,是这类工具的常态,靠的是**存在电脑上的项目文件**接着认路,不是靠我"记得你"。养成收工前说一句、开工前说一句的习惯,这两句话就能补上这个缺口。

## 顺便说清楚:我做不到什么

免得你抱着不对的期待:

- **我做不到"一句话给你一个微信"。** 大的东西可以做,但要拆成很多小步、花很多天,不是一次对话能出来的。第一次玩,从"一个页面、一个按钮"这种大小开始。
- **我做出来的第一版,数据经常是假的。** 为了先让你看到样子,我会先填一些占位的示例数据,看到数字别急着信,直接问一句"这里的数据是真的吗"。
- **要花钱的、要用你账号的事,我不会自己去做。** 买域名、开服务、发布到应用商店这类,我会告诉你要做什么,但需要你自己去决定和付钱。
- **我会出错。** 会理解错你的意思、会写出跑不起来的代码。这不需要你紧张,发现了说一声,我改——这本来就是这套流程的一部分,判断对不对的永远是你看到的效果,不是我说得听起来专不专业。

## 什么时候可以往"更快"的方向学

等你自己完整做过两三个小东西(提出来 → 看见了 → 改到满意 → 存过档),再考虑更快的做法。那之前不用去读更厚的技术教程,也不用因为别人能同时指挥好几个 AI 而觉得自己慢——你现在练的这两下,是以后所有更快做法的基础。

想学更快的时候,直接说"我已经会验收了,给我那份进阶的",我会带你看那份《Orca + Claude 多 Agent 系统教程》。
